# Sampled house states and changes

Detailed windows now derive immutable house-state proposals from their retained Parquet observations. `hogline house-states WINDOW_ID` or `POST /api/windows/{id}/house-states` derives an older compatible window without video access. New windows derive states automatically in the same publication transaction. `GET /api/window-house-states/{id}` returns the full result; catalog summaries and immutable JSON releases retain its version, checksum, input manifest, and context frames.

Use **Inspect sampled house states** on a detailed window, or filter **Find moments** to **Sampled house states** / **House configuration changes**. Search opens the selected proposal first. The comparison includes exact retained endpoint images when available and separately captioned window context. Source links preserve the interval even when an endpoint image was not retained. Reading cached observations never schedules more acquisition.

A stable run requires at least four samples across 1.5 source seconds, four distinct decoded composite images, low measured crop motion, a usable blue-ring reference, unchanged crop/ring geometry, and matching handle positions/colors against both the preceding and first sample. Foreground/ring obstruction, clipped handles, rejected color candidates, gaps, and geometry drift split runs. Zero-detection runs are explicitly `stable_no_handle_detections`: they do **not** establish an empty house. Granite, hidden handles, and missed colors remain unknown. The checks are experimental; a distinct composite image cannot establish that each camera panel is live.

Changes between stable configurations carry the last before and first after original PTS, rational timebase, source seconds, and YouTube links. They require contiguous samples and compatible ring geometry throughout a bracket of at most ten seconds. Changes across missing geometry, camera movement, or larger gaps remain unresolved. Intervening motion/obstruction flags remain visible. Occupied-to-zero-detection changes are only `possible_clearing`; other changes are `handles_appear` or `configuration_changed`. None supplies a played-end boundary, official end number, shot identity, or score.

Runs stay scoped to one bounded window and overhead view. No cross-window identity or physical A/B mapping is inferred. Retained context anchors may be at different times from state endpoints: original endpoint links remain available, and an image from a different instant must not be presented as the exact state. Result size is limited to one MiB; exceeding it publishes an explicit abstention and preserves the original dense observations.

Independent interval labels, frozen day/recording cohorts, and sample-level stability/abstention checks are available through the [house-state benchmark](HOUSE_EVALUATION.md). Retained-anchor-only labels cannot become interval ground truth.

## Development checkpoint, October 28, 2026

A cached-only pass over 28 compatible local windows produced 55 stable runs, predominantly zero-detection runs, and no change brackets. Another 29 windows had older or unavailable dense inputs. This measures output coverage on selectively sampled development data, not detection accuracy or completed-end coverage. No new media was fetched and no games, ends, or accepted scores were created. Synthetic checks cover clearing/appearance/configuration changes, drift, obstruction, gaps, repeated images, timing, immutable reruns, result limits, and release lineage. Independent labels and real clearing footage remain necessary before these proposals can support automatic end reconstruction.
