# Narrowing a board-change gap

Open **Posted board changes → Compare board evidence → Narrow this gap automatically**. The preview shows a few concrete short source intervals, their YouTube links, and one shared storage/worker allowance. Starting it queues the selected windows and then automatically reads only their retained board/clock frames.

The largest remaining gap is sampled first, at its midpoint. Each chosen window is subtracted before selecting another, so samples spread across the uncertainty interval. Compatible completed and running windows are excluded from another decode. Completed windows with unread anchors can be reused for OCR. No other batch's running work is taken over. Failed identical work is reported in the exclusions; candidate exploration is bounded to 128 attempts per preview.

This selection differs from an activity campaign: it does not require another coarse scan or read every cached image in the recording. It uses at most eight windows per round, each 4–30 seconds, and at most 120 OCR anchors per round under the same cumulative budget. Defaults are three rounds of up to three ten-second windows, a 60-second target bracket width, 96 MiB retained growth, and 300 worker seconds. The round limit can be set from one to four. The preview states the maximum total window count and concrete first-round intervals. Pausing, resuming, retrying, and cancelling use the ordinary Processing controls. The request, original board-change evidence, source/method pins, selected intervals, phase history, and costs remain in the batch record.

The timeline is recomputed from the resulting proposed readings. New evidence may narrow a bracket, expose several separate card changes, or leave it unresolved because the board remains unreadable. It never establishes the exact time an end was played. After each round, the worker rechecks the current timeline and chooses the widest remaining bracket within the **original source interval, row color, metadata snapshot, and OCR version**. Later rounds share the same cumulative budget; restarting or resuming never refills it. Each round's plan, observations, and outcome remain in history.

The run stops when the requested target width is reached, the finite round limit is reached, no further windows fit, or no current matching bracket remains. These outcomes are distinct: loss of readable evidence is not reported as reaching the target. Resource exhaustion pauses for inspection/resume. Reaching a narrow bracket still does not accept a score or establish event-detection accuracy. No recurring or unbounded processing is scheduled. Earlier screenshots, observations, and released datasets remain historical evidence.

```sh
uv run hogline refine-board CHANGE_ID --windows 3 --rounds 3 --target-seconds 60
uv run hogline refine-board CHANGE_ID --windows 3 --rounds 3 --target-seconds 60 --max-growth-mb 96 --max-worker-seconds 300 --enqueue
uv run hogline work
```

The UI uses `POST /api/board-refinement/preview` and `POST /api/board-refinement/batches`. Publication rechecks the reviewed plan hash. A changed timeline, source manifest, or matching work invalidates the preview. Current event IDs are available in `broadcast.board_timeline.changes` from the catalog or JSON export.

Tests cover deterministic gap selection, no side effects from preview, stale previews, a too-small gap, preserving other batches' work, reuse of unread anchors, and excluding unrelated cached frames from OCR. Multi-round tests additionally cover early target completion, unresolved round limits, source/color/scope restrictions, restart, cumulative costs, and transaction rollback during publication of a later round. Real-media checks measure orchestration and evidence quality; they do not establish held-out detection precision.

The initial single-round real Sheet 4 refinement sampled three ten-second windows inside the 330–7395-second bracket. Its three decodes and ten retained-frame OCR units completed in 37.34 worker seconds with 24.28 MiB reserved. The resulting timeline separated the original broad interval into three proposed card-change brackets of approximately 29 minutes each. The red end-5 card became readable between source times 3867 and 5626.267 seconds; before/after crops and exact source links were checked in the browser. Those timestamps bound a posted-card change, not when end 5 finished.

The multi-round follow-up on that red end-5 bracket used three rounds of three windows. It stopped at its three-round limit with a 101.067-second bracket, using 112.76 worker seconds and 74.37 MiB. A separate bounded follow-up allowed two rounds of one window and reached its 60-second target after the first round: **4917.2–4963 seconds (45.8 seconds)**. That follow-up used one decode and four OCR units, 13.78 worker seconds, and 9.50 MiB. The browser comparison shows three repeated earlier readings without the card and three repeated later readings with it, each with its own original frame and YouTube timestamp. No game result or end completion was accepted. Some intervening frames produced conflicting readings from white clothing near the board; those frames broke the repeated-reading sequence instead of voting for a change.
