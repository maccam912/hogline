# Score disagreement review

The workbench compares current repeated-board score proposals with saved played/blank ends. A disagreement appears only when the official end number is known, the reader and source manifest are current, every supporting frame is present and belongs to the claimed source/time, and the entire repeated-reading interval falls inside one of that game's linked source spans. Missing readings, unknown scores, missing end numbers, stale inputs, retired games, and evidence outside the game do not establish a disagreement or agreement.

The **Score disagreements** badge counts open discrepancies. Each comparison shows the saved score and its acceptance, its source evidence, all qualifying board alternatives (including any that agree), and their timestamp links. A discrepancy can be an OCR error, a missing or delayed card, a wrong game span, or a score that needs correction. No automated result changes a saved score, acceptance, boundary, or final outcome.

**Record review decision** requires a reviewer and reason. Choose **Reviewed: keep saved score** to acknowledge this exact discrepancy, or **Keep open for review** to retain/reopen it. Acknowledgment does not promote a proposed score to confirmed. **Open game review** uses the existing revisioned editor for an explicit correction. The discrepancy disappears if the saved score subsequently agrees; its review history remains.

Every decision is append-only and checksum-protected. It freezes the discrepancy, saved game revision, score, board proposal IDs, source manifests, reader version, frames, and timestamp links. Optimistic review revisions reject stale/concurrent saves. Any game revision or different proposal evidence creates a new discrepancy ID; earlier acknowledgments cannot silently apply. Drafts cannot be discarded by closing the modal, switching comparisons, or opening a different game without using Save or Discard.

JSON dataset releases include `score_disagreements`: current comparisons for exported ends plus the full review audit history. Confirmed exports retain their existing game/end eligibility rules; audit history is not a confirmed score. Export validation recomputes current disagreements from the included saved ends and board proposals, checks review hashes and consecutive revisions, and verifies the displayed latest decision and open count. It rejects inconsistent publications.

The API provides `GET /api/score-disagreements` and `POST /api/score-disagreements/{id}/reviews`. No video fetch or OCR is performed by these operations. Tests cover matching scores, opposing colors, blank ends, competing readings, source/model drift, time/source membership, missing evidence, stale reviews, game corrections, retired interpretations, and forged exports. An isolated synthetic browser fixture exercised acknowledgment, unchanged score/acceptance, protected drafts, explicit game correction, and retained audit history. No real game was confirmed or changed during this UI check.

The UI check also exposed status messages hidden behind native dialogs. Notices now appear inside the open dialog so validation errors and unsaved-draft guidance remain visible and accessible.
