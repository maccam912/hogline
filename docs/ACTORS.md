# Automatic perspective person fragments

Detailed windows now analyze both perspective camera crops automatically when the pinned local person model is installed. This is the first stage toward associating deliveries with game participants. It runs under the same finite frame, cache-growth and worker-time allowances as overhead analysis. No separate operator launch or video download is needed for new windows.

The optional detector uses OpenCV DNN with the [OpenCV Zoo YOLOX-s COCO model](https://github.com/opencv/opencv_zoo/tree/48b10fa505aeb51fbd127fc60a5c660040e823b7/models/object_detection_yolox) at the linked commit. The model directory is Apache-2.0 licensed. The required ONNX is 35,858,002 bytes with SHA-256 `c5c2d13e59ae883e6af3b45daea64af4833a4951c92d116ec270d9ddbe998063`. Keep it at `DATA_DIR/models/yolox-s-coco/object_detection_yolox_2022nov.onnx` or point `HOGLINE_PERSON_MODEL` to it. The current local archive already has this model. Weights stay outside the public repository; no model download occurs implicitly.

Inputs use a 640×640 RGB top-left letterbox with padding 114 and raw float pixel values. Person proposals require person to be the highest-scoring COCO class, objectness×person score at least 0.35, and NMS at 0.5. Scores remain uncalibrated. Original crop coordinates are restored after letterboxing. Padding-only/tiny boxes are excluded; more than 64 people in a crop causes an explicit stage abstention. Missing, corrupt or unloadable models and failed inference are recorded as unavailable, while overhead results can still publish. Lease, pause, cancellation, cache and worker-budget checks still apply to the entire window.

Perspective observations live in a separate compressed Parquet artifact, with original PTS/timebase, source seconds, frame hashes, crop dimensions, model hash and input manifest. Anonymous fragments associate body positions and torso clothing-color histograms within a single view/window. The head is omitted from the descriptor. Gaps, excessive movement/scale changes, clothing mismatches, clipped/tiny bodies, ambiguous assignments and strongly overlapping similarly colored people break associations. Fragments need three samples across at least one second. There is no interpolation across missing people or cross-camera identity fusion.

Each fragment keeps source-linked samples, pixel displacements and low-posture cues. It has no named person, game participant or delivery assignment yet. People on adjacent sheets and spectators can be included; camera geometry and sheet membership are unresolved. Low posture alone cannot establish a thrower. These proposals must not be counted as distinct players, shots or named weight measurements. The next stages must combine sheet/hack geometry, stone motion, delivery timing and participant/roster evidence, with uncertainty review for unresolved associations.

`hogline trace-actors WINDOW_ID` or `POST /api/windows/{id}/actors` re-derives fragments from cached perspective observations without loading the model or fetching video. Earlier overhead-only windows need explicit reanalysis to acquire perspective observations. `analyze_actors=false` disables the optional stage for an individual window. Immutable JSON releases include actor results and input references; the API exposes summaries in the catalog and full results at `/api/window-actors/ID`.

Use **Inspect automatic person fragments** on a compatible window, or filter **Find moments** to **Anonymous person fragments**. Search opens the selected fragment first. Person boxes are drawn only when a retained frame matches the sample's exact source time, PTS/timebase and crop dimensions. Other sample times keep their original source links, with no box painted onto a different instant. The selected fragment and exact-frame overlay were checked in the browser on the Sheet 3 example below.

## Development check, October 28, 2026

A cached-image trial on 14 perspective crops across Sheets 1, 3, 4, 5, 7 and 8 proposed 32 people and none on the inspected quiet views. This is a selected feasibility check, not measured precision/recall. A new twelve-second Sheet 3 window at source 01:30:00 then ran the actual decoder, model, fragment association and export pipeline: 24 samples per view, 21 anonymous fragments, 8.76 MiB retained/reserved and 15.19 measured worker seconds, within a 32-MiB/120-second allowance. Twenty-one fragments do not mean twenty-one people; interrupted associations intentionally create multiple fragments. No game, named identity, delivery or score was accepted.

Synthetic tests check non-square letterboxing, padding/clipping, NMS, RGB preprocessing, missing/corrupt models, bounded outputs, clothing and overlap ambiguity, gaps, original timing, cached-only derivation, failure abstention, output-size limits, API integrity and release lineage. Actual person/thrower precision and association recall still need independent game-specific labels.
